# Sprint 4：世界修改闭环试点任务卡

## 范围、状态与估点

本页展开[路线图](./agent-collaboration-sprints.md)的 S4-01～S4-05。用户从问题或补充要求得到改动提案，采用后安全保存与自动复核，失败或刷新后仍回到同一现场。业务 Story 尚未实施。

全部卡片为 **Not Ready**，直至 S1-06 的运行承接、proposal/commit/verification合同和对应[Sprint 3](./agent-collaboration-sprint-3.md)依赖完成。以下错误类别和字段表达要求，不预定尚未证明的HTTP路径或数据库表；根集成人在Spike产物中冻结正式请求/响应、模型与状态图后才能实施。

提案/采用/复核共用依据组合：contentRevision + decisionRevision + assessment/run引用；字段名可在Spike调整，但内容与作者决定必须同时受版本保护。世界内容未变、作者留白或保护决定已变时，旧方案也必须失效。来源UI消费相同组合，不只比较baseRevision。

原候选23点。将深化建议与整合、审阅与执行恢复分别验收后重新估算为 **25相对点**，不是单个Sprint固定承诺或日程。每张不超过5点。

## Ownership 与运行边界

真实世界入口为 `server/src/services/world/WorldService.ts`、`worldImprovementService.ts`、`worldSnapshotService.ts`；HTTP在 `server/src/modules/setup/world/http/`。拟建 maintenance 模块与 Prompt 子目录沿用Sprint 3的归属；通过门面复用已有结构投影、Prompt Runner和索引刷新。

前端真实入口：`client/src/pages/worlds/WorldWorkspace.tsx`、`components/workspace/WorldConsistencyTab.tsx`、`WorldDeepeningTab.tsx`、`WorldHandbookEditor.tsx`。拟建 `components/workspace/maintenance/`按提案审阅、决定、执行状态分责任组件。若入口实际路径在开工基线变动，复核后记录，不另造同名总控。

Runtime Agent独占写入/持久化/复核恢复；Prompt Agent独占维护 Prompt输出；UI Agent独占前端组件。根集成人独占 shared/types、schema/迁移、registry/catalog、API/queryKeys和HTTP挂载，依次接线。世界维护运行使用S1-06选定门面：不新增第二套小说生产链，不将样本任务冒充小说导演任务，不把仅内存的request handler当可恢复执行。

## S4-01：从问题和要求形成修改提案

作为作者，我希望AI给出具体修改和创作取向，让我能读懂、比较并决定采用，而不用自行寻找字段。

- 点数5，P0；Not Ready → S3-02b、04、05b、06b通过且proposal契约冻结。Prompt Agent owned维护提案/影响资产；Runtime Agent随后接maintenance应用服务，registry和共享请求根集成人。
- 子任务：读取问题身份、评估依据、当前结构和作者决定；AI输出稳定目标、具体patch、baseRevision、保留要求、理由及影响；校验范围/引用；保存备选方案、输入与实际模型来源；生成期间定位同一来源现场。
- 非范围：生成即自动修改；模拟全书依赖分析；默认覆盖人工设定；字符串路由识别作者意图。
- AC1：提案生成和“另一方案”零世界内容写入，旧提案/创作取向仍可查看。
- AC2：提案包含可读差异、稳定实体目标和依据；引用不存在或schema无效的输出不进入可采用状态。
- AC3：过期评估、内容版本或作者决定版本变化明确标为过期；提案保存完整依据组合，不允许基于失效报告或旧留白要求直接采用。
- AC4：锁定规则、作者留白、认知边界和禁止修改范围进入required context；越界patch被安全校验拒绝，不靠AI自称遵守。
- AC5：模型失败保留输入和已生成其他方案；重试复用同一请求身份及其范围，不偷偷扩大改动。
- 检查：拟建 `server/tests/worldMaintenanceProposal.test.js`；mock结构化Runner覆盖实体引用、保护边界、失效版本、另一方案、失败恢复；目录纳管检查。
- Done证据：两种方案样例、实际模型/依据版本、零写入计数、越界拒绝结果；未真实抽样时明确提案质量缺口。

## S4-02：采用提案的原子事务提交

作为作者，我希望采用时只修改我确认的内容，多次点击或其他编辑不会造成覆盖和重复执行。

- 点数5，P0；依赖S4-01、S3-02a/b及S1-06提交/运行承接合同。Runtime Agent owned maintenance提交application/store；共享schema及HTTP接线根集成人。
- 子任务：绑定world/proposal/选择范围/提交身份；事务CAS与保护校验；应用patch后校验完整结构和引用；写内容/兼容字段/revision/前后证据/提案采用记录；持久化待复核状态；事务外触发既有索引刷新。
- 非范围：无证据部分采用、全局依赖撤回、隐式同步到本书、无范围自动授权。
- AC1：同一采用身份重放只写一次、版本递增一次；双击和响应丢失均返回原提交结果。
- AC2：内容或作者决定版本失效、资源不匹配、越权或锁定冲突零内容写入；事务同时检验依据组合及当前保护，决定改变而内容未变也拒绝旧方案，界面可重新审阅新差异。
- AC3：结构、兼容投影、版本、前后证据、采用与待复核状态同事务；任一步失败全部回滚。
- AC4：选中patch有依赖时明确要求采用依赖组或拒绝；不能只应用一半然后normalization静默补/删关系。
- AC5：样本采用不修改关联NovelWorld、正文或canonical事实；索引异常不撤销已成功提交，也不宣称验证完成。
- AC6：提交成功而事件派发中断，持久待复核仍可由既定恢复门面发现；不能依赖浏览器再次点击才能补救。
- 检查：`worldMaintenanceCommit.test.js`扩展采用场景；隔离事务竞争、注入各持久化步骤失败、提交后响应丢失、依赖patch、跨world、索引失败。
- Done证据：原子提交/幂等结果、失败零写入、前后版本和待复核记录；未证明提交后恢复门面不得公开采用入口。

## S4-03：提交后的验证与同现场恢复

作为作者，我希望保存成功和体检失败能区分，稍后继续复核不再重复修改世界。

- 点数3，P0；依赖S4-02、S3-05b及运行承接租约/投影证明。Runtime Agent owned维护复核application/store；来源任务投影复用S1-06选定门面，根集成人接共享query/API。
- 子任务：分离已提交/待复核/复核中/完成/未完成/过期观察；只对提交后版本执行评估；恢复只续未完成阶段；持久化问题结果与证据；可读投影带稳定sourceRoute。
- 非范围：体检失败回滚作者内容；把残留风险当全球导演失败；在运行记录中重试。
- AC1：提交后AI超时显示“内容已保存，待复核”，新内容可读；再次继续不重复应用patch。
- AC2：进程在提交后或复核中中断，恢复读取相同commit和输入版本；运行租约避免两Worker同时推进。
- AC3：复核期间世界或作者决定改变，按同一依据组合将旧结果标过期，不把新版问题标已解决；保留原观察。
- AC4：只有匹配当前依据的复核证据产生解决结果；残留风险继续展示提案/决定，不伪造通过。
- AC5：索引失败作为独立资料债可恢复；恢复操作只在世界源页，运行记录仅状态/来源导航。
- 检查：拟建 `worldMaintenanceRecovery.test.js`；提交后crash、复核crash、租约竞争、内容变化、AI失败、索引失败、恢复重放计数。
- Done证据：持久恢复轨迹、内容提交次数1、真实来源路由、未完成和过期投影；用户UI验收缺口单列。

## S4-04a：关键问题与推荐答案

作为新手，我希望只决定最重要的缺口，先看到AI推荐及故事后果，避免空白填表。

- 点数3，P1；依赖S4-01、S3-04、S3-06b的评估/决定合同。Prompt Agent owned维护问题/推荐答案资产；Runtime Agent接现有深化门面读取，schema/root集中。
- 子任务：根据当前可信结构、作品用途和已决定内容生成少量高影响问题；给出推荐与备选及后果；保存目标引用和推荐版本；过滤已有已确认决定通过AI结构化理解完成。
- 非范围：固定缺省问题池兜底；每个题材要求魔法/阵营数量；仅把新手表单换聊天外观。
- AC1：问题附默认推荐、备选差异和目标实体，不要求作者理解内部字段/层级。
- AC2：已明确回答或决定的同一缺口不再重复追问；AI无法判断时说明不确定，不靠问题字符串去重充当理解。
- AC3：现实题材可以没有战力体系，AI依据当前作品范围解释缺口而非普遍完整度门槛。
- AC4：问题生成失败保留已有问题/输入，不以硬编码英文问题制造成功；选择答案前不改世界。
- AC5：推荐依据版本变化时提示重新审阅，旧建议不能成为当前默认已确认答案。
- 检查：拟建 `worldDeepeningRecommendations.test.js`；mock AI判断、已决定缺口、无能力体系、失败/过期/零写入。
- Done证据：新手可读问题与推荐、重复追问回归、失败保留和版本说明；真实提问质量抽样另记。

## S4-04b：回答整合为同一修改提案

作为作者，我希望回答后能看到手册具体改变，且后续创作使用的就是这些改变。

- 点数3，P1；依赖S4-04a、S4-01/02/03、S3-03b。Runtime Agent接 `worldImprovementService.ts` 深化路径与maintenance提案；Prompt Agent负责整合资产，双方串行；Gateway/同步由原Runtime门面适配。
- 子任务：答案携带问题身份/依据与提交身份；AI整合到可信结构patch；沿同一提案/采用/复核合同执行；旧QA保留来源及状态解释；呈现生成链引用边界。
- 非范围：答案直接拼Q/A后称已生效；自动把旧 integrated全文重建骨架；自动同步样本到所有小说。
- AC1：提交答案形成可审阅结构提案，作者采用后结构、兼容摘要和复核一致；重复提交不重复追加。
- AC2：旧 integrated记录保留为历史回答，不能被自动当作已验证结构变更；legacy-text世界走明确兼容策略。
- AC3：失效问题或越界目标不写；生成整合失败答案仍保留为未兑现，不显示已完成。
- AC4：本书采用的结构通过Gateway读取；样本修改只影响样本，关联小说通过明确同步/适配才使用新结果。
- AC5：采用后复核失败沿用S4-03状态，恢复不重新提交答案或重复应用。
- 检查：`worldDeepening.test.js`相关回归加拟建整合行为；可信骨架、旧integrated、重复答案、结构引用、Gateway读新实例、样本隔离、提交后恢复。
- Done证据：回答→proposal→commit→验证→Gateway/样本边界链路与重复计数；未接通生成消费不得称“补齐已生效”。

## S4-05a：问题与提案原地审阅

作为作者，我希望在一个现场理解问题、比较方案和读改动，不必切页摸索编辑位置。

- 点数3，P1；共享评估/提案/决定响应冻结后可联调，业务Done依赖S3-05b、06b、S4-01。UI Agent owned `WorldConsistencyTab.tsx`及拟建maintenance审阅组件；`WorldWorkspace.tsx`同owner串行，API/queryKeys根集成人。
- 子任务：问题详情显示证据/影响/版本；并列或逐项切换方案；展示精确差异/保留内容；自改精确定位已有手册编辑器；空/加载/错误/过期/未知状态分开。
- 非范围：复杂全局三栏、把前端猜测当任务状态、在TaskCenter操作、默认浏览器测试。
- AC1：问题、推荐方案、其他方案、修改位置可在同现场访问；长标题/状态不越界且正文可阅读。
- AC2：不同方案保留来源，不因切换丢已输入反馈；切换world或issue时旧请求不覆盖新现场。
- AC3：手动编辑携带准确实体定位与问题上下文；保存后走真实安全写入，不靠mark resolved代替处理。
- AC4：未知/未完成/过期与无问题分开；界面不按旧分数推断新版通过；比较内容+决定+评估依据组合，不漏掉仅决定变更的过期。
- AC5：低边框层级、项目自有 primitives、语义变量；用户文案讲操作与效果，不写迁移/实现旁白。
- 检查：前端typecheck；有意义的world/issue异步隔离行为检查；className不加镜像测试。用户验收审阅、长文本、方案切换、自改定位。
- Done证据：真实API消费、状态矩阵、跨资源响应隔离结果、用户UI验收或明确缺口；mock仅联调材料。

## S4-05b：采用、作者决定与刷新恢复

作为作者，我希望确认一次后知道保存和复核分别到哪，刷新回来仍能继续处理。

- 点数3，P0；依赖S4-05a、S4-02/03、S3-06b及根集成人冻结命令/API/queryKeys。UI Agent owned维护动作/执行反馈/恢复组件和WorldWorkspace接线。
- 子任务：绑定proposal/commit/run到URL或正式持久资源；pending防重复；提交冲突重新审阅；采用后差异和复核结果；留白/暂定/拒绝动作；原地恢复与只读记录来源链接。
- 非范围：前端只禁按钮充当幂等；本地storage作为提交事实；未完成后端公开“采用并验证”；自由文本状态判定。
- AC1：采用真实pending，双击仅同一提交身份；提交内容与决定依据组合，冲突零内容写入并保留作者输入与原方案。
- AC2：内容已保存而验证失败单独显示，可读新手册并从源页续复核；刷新不重复采用。
- AC3：拒绝方案不改内容；留白/暂定保存到真实决定合同并使评估依据失效，不只是隐藏清单行。
- AC4：深链接/刷新恢复同world、issue、proposal和运行；旧响应仅更新原资源缓存，不能串现场。
- AC5：当前修订结果仅在真实验证证据到达后显示已解决；“不是问题”保留作者说明和范围，与验证通过区分。
- AC6：运行记录只查看进度/错误/来源，重试或继续复核按钮位于当前世界；局部风险不呈现为全书生产失败。
- 检查：采用命令身份、刷新查询、状态投影、资源切换和提交后复核失败行为；client typecheck。用户验收采用→刷新、拒绝、留白、冲突、自改后复核。
- Done证据：真实端到端提交/复核/决定记录与恢复结果，pending与冲突样例，用户验收状态；未完成后端仅内部联调。

## 并发 Wave 与发布门

1. Wave 0：复核上表逐卡S3依赖；根集成人冻结proposal、commit、复核运行、错误、API/queryKeys和迁移。合同未冻结只做Spike补证，不抢写共享文件。
2. Wave 1：Prompt Agent做S4-01资产；Runtime Agent做提交/复核contract的owned适配，正式S4-02实施等待提案合同；UI Agent做S4-05a只读审阅。mock不算业务Done。
3. Wave 2：Runtime Agent串行完成S4-01应用接线、S4-02与03；Prompt Agent做S4-04a及04b整合资产；UI Agent按真实后端接S4-05b。
4. Wave 3：Runtime Agent接S4-04a/b；UI Agent联通深化到同一提案现场；根集成人集中构建、故障注入、review和用户验收记录。

未证明租约/持久恢复、原子提交或双版本来源，相关入口保持关闭。Ready不等于Done，单独typecheck不证明事务/恢复；前端UI由用户验收，不默认跑浏览器/截图。使用mock transport、mock persistence或隔离临时SQLite，不调用付费模型或写桌面库做回归；真实模型抽样另行记录。

根集成人维护wiki、适用发布记录并按阶段提交；子Agent不commit/switch/merge。feature经beta组合验证后才到main。不得重置/删除用户数据，不自动改世界来源副本或发布正文；局部世界/资料债可继续处理，小说quality-first明确暂停仍等待显式恢复。跨资产、全书依赖撤回和总任务预算留在对应Backlog Spike，不能凭新界面宣称实现。
