# 真人多人协作：Sprint 与 Story 分解

## 背景与现状

目标是让多位真人作者、编辑和审阅者共同完成一本小说，同时保留 AI 自动导演、章节生产、资产维护和来源现场恢复能力。

当前系统仍是单机单作者模型：`authMiddleware` 直接放行，`Novel`、`World` 等核心资源没有统一工作区和成员归属；RAG 的 `tenantId/ownerId` 只用于资料范围，不能充当用户身份或作品权限。桌面数据库适合个人创作，不适合作为多台设备同时写入的共享事实源。

因此采取“异步协作优先、实时共编后置”的路线：先建立身份、权限、版本、评论和修改建议，再增加在线状态与同章节实时编辑。已有个人模式保持可用；协作工作区采用中心服务作为权威存储，不通过复制 SQLite 文件实现同步。

## 产品边界

- 角色固定为 `owner / editor / commenter / viewer`。产品展示角色，服务端最终检查细粒度 capability；不在各路由堆角色字符串判断。
- 评论和建议不是正文事实。只有有权成员明确采用，才通过资源版本安全写入进入正式内容。
- AI 任务记录发起人、授权范围、费用归属与模型策略；退出团队不会改写历史操作者。
- 运行记录继续只读；邀请、评论、采用、冲突处理、AI委托和恢复均在作品或资产来源页。
- 首版不承诺 Google Docs 式逐字实时共编。章节实时共编要经过 CRDT/OT、AI写入桥接、撤销边界和离线策略 Spike。
- 个人桌面模式不强制登录。进入协作工作区才需要身份与在线连接；离线阶段先只读缓存，不做双主写入。

## C0：身份、工作区与权限基础

### C0-01 协作部署与身份边界 Spike（3 点）

- 用户价值：明确个人本地作品和在线协作作品如何进入、保存和恢复。
- 状态/Owner：Ready（Spike）；根集成人，联合桌面/服务端 owner 只读审计。
- 任务：冻结个人模式、协作工作区、中心 PostgreSQL、附件存储、会话、连接失败和数据驻留边界；定义桌面/网页相同身份语义。
- AC：个人模式无需登录且不被隐式上传；协作写操作只指向中心权威服务；服务不可用不在本地伪造成功；导出/退出/删除的责任和备份边界明确；不以 RAG tenant 当用户系统。
- 检查/证据：部署图、信任边界、失败时序、数据分类与后续卡解锁清单。
- 非范围：生产认证、局域网点对点、自动上传用户库。

### C0-02 用户身份、会话与设备登录（5 点）

- 用户价值：合作者能以自己的身份进入，操作可追溯且会话可撤销。
- 状态/Owner：待 C0-01；平台身份 Agent。拟建 `server/src/platform/identity/`，HTTP/共享类型由根接线。
- 任务：用户、身份提供方、会话、设备、撤销与当前主体；替换 passthrough auth 的协作路径；个人本地路径使用受限 local principal。
- AC：无会话不能读协作资源；撤销后新请求立即失败；会话/日志不泄露令牌；同账号多设备主体一致；local principal不能访问在线工作区；鉴权失败不降级成匿名写入。
- 检查/证据：mock身份提供方、过期/撤销/重放/跨设备行为测试和安全审计。
- 非范围：自建密码学、把 API key 当用户令牌、社交登录全厂商一次接完。

### C0-03 工作区、成员与邀请生命周期（5 点）

- 用户价值：作品所有者能邀请成员、调整职责并移除访问。
- 状态/Owner：待 C0-02；协作 Runtime Agent。拟建 `server/src/modules/collaboration/membership/`。
- 任务：Workspace、Membership、Invitation；邀请到期/撤销/接受；owner移交和最后owner保护；作品关联工作区。
- AC：邀请只能由有权成员创建；同邀请重放幂等；过期/撤销邀请不能加入；移除成员后零新访问但历史署名保留；最后owner不能直接退出；跨工作区ID猜测返回无资源或拒绝且零泄露。
- 检查/证据：隔离数据库生命周期、竞态、枚举攻击与owner移交测试。
- 非范围：组织账单、公开链接编辑、自动邀请通讯录。

### C0-04 Capability 权限服务与资源归属接线（5 点）

- 用户价值：查看者不能改稿，评论者不能采用，编辑者也不能管理成员或越权运行 AI。
- 状态/Owner：待 C0-03；权限 Runtime Agent；根独占共享类型/HTTP接线。
- 任务：角色到 capability 策略；小说、章节、世界、人物、规划、资产、AI任务的资源归属解析；应用服务写边界统一 authorize；查询按工作区范围过滤。
- AC：服务端检查而非只禁按钮；跨工作区读写零泄露/零写入；AI运行、费用、采用建议为独立能力；后台 worker 从保存的授权快照验证工作区；角色变化后新命令使用新权限；运行记录仍无任务变更能力。
- 检查/证据：role×resource×action矩阵和所有核心门面的拒绝/允许行为测试。
- 非范围：基于自然语言猜权限、每条路由复制角色判断、字段级自定义ACL首版。

### C0-05 现有个人数据的非破坏兼容与迁入（3 点）

- 用户价值：已有小说继续可用，作者可以明确选择把副本迁入协作空间。
- 状态/Owner：待 C0-03/04；数据迁移 owner，破坏性步骤仍需单独授权和备份。
- 任务：默认个人工作区/本地主体兼容；“复制到协作空间”预检、引用清单、附件/资产范围、幂等导入及失败恢复；原库不自动改归属。
- AC：升级不删除或上传旧数据；预检展示范围；重复导入不复制半套关系；失败保留原作品并可重试；迁入副本和本地原件ID/来源清楚；不对用户库执行 reset。
- 检查/证据：临时SQLite→隔离协作库演练、关系计数、失败注入和备份要求。
- 非范围：自动双向同步本地与云端、静默合并两本书。

### C0-06 权限覆盖、审计与安全发布门（3 点）

- 用户价值：协作上线前证明成员只能接触被授权作品。
- 状态/Owner：待 C0-02～05；安全验证 owner。
- 任务：建立核心HTTP/worker/事件/导出/附件/RAG权限覆盖表；审计读取/写入/AI发起/成员变化；敏感字段脱敏。
- AC：所有协作资源入口有主体与工作区；worker不能绕过授权快照；RAG tenant与workspace明确映射；导出与附件签名有范围/过期；审计失败不伪装业务成功且策略明确；高危缺口阻塞beta。
- 检查/证据：自动授权矩阵、IDOR/跨租户测试和未覆盖入口清单为零或显式关闭。
- 非范围：替代专业渗透测试、公开上线。

## C1：评论、修改建议与异步协作

### C1-01 协作资源 revision 与统一变更身份（5 点）

- 用户价值：两人同时修改不会互相覆盖，所有变更能定位作者和依据版本。
- 状态/Owner：待 C0-04；版本 Runtime Agent；复用各资源 CAS，缺失资源先补版本。
- 任务：统一 operationId、actorId、baseRevision、resourceRef、before/after证据；章节/世界/人物/规划适配；AI actor和human initiator分开。
- AC：同base竞争只一方成功；重放只写一次；actor不可由客户端伪造；AI变更同时记录发起人与执行者；版本冲突零写入；旧资源无revision按兼容门处理。
- 检查/证据：四类资源竞态、幂等、跨成员和worker提交测试。
- 非范围：全系统撤回、实时逐字同步。

### C1-02 锚定评论、讨论与解决声明（5 点）

- 用户价值：编辑可以针对章节片段、世界条目或人物设定讨论，不直接改正式内容。
- 状态/Owner：待 C0-04、C1-01；协作 Runtime/UI 串行。
- 任务：Thread/Comment、资源锚点、上下文摘要、回复、解决/重开、删除策略；锚点漂移后显示原证据和当前定位状态。
- AC：commenter可评论但不能改正文；跨资源评论拒绝；内容修改后评论不错误附到新文本；解决是讨论状态而非内容已验证；删除保留必要审计并遵守权限；刷新恢复原讨论。
- 检查/证据：锚点漂移、回复竞态、权限、删除/恢复行为及用户UI验收。
- 非范围：评论自动进入正史、运行记录评论、AI自动采纳讨论。

### C1-03 @提及、收件箱与来源导航（3 点）

- 用户价值：被点名的成员能回到准确作品与讨论位置。
- 状态/Owner：待 C1-02；通知 Runtime/UI Agent。
- 任务：结构化mention目标、站内收件箱、已读状态、稳定sourceRoute；外部通知仅消费同一事件。
- AC：只能提及当前工作区有效成员；显示名文本不触发伪提及；重复事件不重复通知；退出成员不再收到新通知；链接回正确资源；收件箱操作不改变创作任务。
- 检查/证据：mention解析使用显式成员选择/结构化ID，不用正则核心识别；事件幂等与路由测试。
- 非范围：邮件/推送全渠道、运行记录恢复按钮。

### C1-04 修改建议、差异与作者说明（5 点）

- 用户价值：合作者或 AI 可以提出改法，正式内容在采用前保持不变。
- 状态/Owner：待 C1-01/02及对应资源安全提交；Prompt建议由Registry资产承接。
- 任务：Suggestion保存baseRevision、目标、patch、理由、保留要求和来源；人工建议与AI建议同一审阅合同；备选与拒绝历史保留。
- AC：创建建议零内容写入；commenter可建议但不能采用；过期建议明确失效；AI理解使用结构化输出而非关键词路由；保护内容越界建议不可采用；切换方案不丢讨论。
- 检查/证据：人工/AI建议、非法引用、过期和权限矩阵测试。
- 非范围：自动采用、把评论当Prompt全文无限注入。

### C1-05 建议采用、冲突审阅与复核（3 点）

- 用户价值：有权成员采用时看到当前差异，冲突后可以重新比较而不是覆盖。
- 状态/Owner：待 C1-04和资源CAS；Runtime采用 owner，UI只消费命令。
- 任务：采用事务、部分范围、operationId、保护复查、冲突新diff、采用后AI复核/资料债；来源页恢复。
- AC：权限/baseRevision/保护任一失败零写；双击仅一次；部分采用保持引用完整；采用者与建议者分别记录；复核失败显示已保存待复核；任务中心仅导航来源。
- 检查/证据：竞争采用、成员角色变化、部分patch、响应丢失和复核失败测试。
- 非范围：全局自动合并、采用后自动修改别书资产。

### C1-06 活动时间线、成员视图与异步验收（2 点）

- 用户价值：团队知道谁做了什么、哪些内容待自己处理，同时正文仍是主界面。
- 状态/Owner：待 C1-02～05；UI Agent，活动投影只读。
- 任务：作品级活动、成员头像/角色、待我处理过滤、变更来源；低边框呈现，正文和一个主动作优先。
- AC：活动来自持久事件而非前端猜测；历史成员署名保留；加载错误不等于无活动；只读者看不到无权限操作；时间线不包含秘密或全文Prompt；移动端不挤压正文。
- 检查/证据：投影/权限/分页测试、client typecheck和用户UI验收。
- 非范围：在线光标、实时聊天、任务中心操作化。

## C2：在线状态与章节实时共编

### C2-01 在线状态和软编辑提示（3 点）

- 用户价值：进入章节前知道谁正在查看或编辑，减少无意冲突。
- 状态/Owner：待 C0/C1；实时平台 Agent。
- 任务：短租约presence、心跳、查看/编辑意图、断线过期、隐私可见范围。
- AC：断线自动过期；presence不授予写权限；同用户多设备区分；跨工作区不可见；心跳失败不锁死文档；不把在线提示当硬锁。
- 检查/证据：fake clock、多设备、断线和权限测试。
- 非范围：真实内容同步、监控用户输入内容。

### C2-02 实时共编与 AI 写入模型 Spike（3 点）

- 用户价值：团队先明确实时编辑如何与AI改稿、版本、撤销及发布保护共存。
- 状态/Owner：Spike；待 C1 与章节版本合同。根集成人组织平台/章节/UI评审。
- 任务：比较 CRDT/OT；定义文档快照、更新日志、持久边界、AI大patch桥接、undo归属、连接恢复和压缩；选择库前做许可证/维护审查。
- AC：人工逐字更新与AI候选采用不双写；发布/锁定边界可阻止更新；服务重启可恢复；撤销只撤本人成果或明确范围；编辑日志不无限增长；不把WebSocket在线等同保存成功。
- 检查/证据：决策记录、原型时序、失败模式和生产卡解锁条件。
- 非范围：生产代码、世界/规划实时表格共编。

### C2-03 实时网关、认证与房间隔离（5 点）

- 用户价值：获授权成员稳定进入正确章节，断线重连不串书。
- 状态/Owner：待 C2-02；实时平台 Agent。拟建 `server/src/platform/realtime/`。
- 任务：认证握手、workspace/novel/chapter房间、连接续期、背压、重连游标、事件幂等与可观测性。
- AC：令牌撤销后连接关闭；跨工作区订阅拒绝；重连不重复更新；慢客户端不拖垮房间；日志脱敏；水平扩展/单实例限制明确。
- 检查/证据：mock socket、多房间、撤销、重连、背压与进程重启测试。
- 非范围：业务文档算法、公共匿名房间。

### C2-04 章节协作文档与持久快照（5 点）

- 用户价值：多人编辑同一章时文本最终一致，已保存版本可供AI和生产链读取。
- 状态/Owner：待 C2-02/03；章节协作 Runtime Agent。
- 任务：章节协作文档、增量更新、快照压缩、正式revision提交、发布/锁定检查、旧普通编辑器兼容策略。
- AC：并发插入/删除最终一致；重启从快照+日志恢复；持久快照才进入章节事实源；锁定后新更新拒绝；普通CAS客户端不会覆盖活跃实时文档；损坏更新隔离且保留上次快照。
- 检查/证据：确定性并发fixture、压缩/恢复/旧客户端与故障注入测试。
- 非范围：AI自动写、世界结构共编、完整格式化文档编辑器。

### C2-05 AI 建议与实时文档安全桥接（5 点）

- 用户价值：AI改稿不会突然覆盖正在输入的合作者，团队先审阅再采用。
- 状态/Owner：待 C1-04/05、C2-04；章节/Prompt owner串行。
- 任务：从稳定快照生成建议；锚定AI patch；采用时映射当前协作文档并检测语义/位置冲突；原子记录AI/发起人/采用人；复核保存边界。
- AC：生成建议不冻结他人输入；base改变后不盲目套patch；有歧义进入冲突审阅；采用广播一次且持久；AI任务失败不破坏当前文档；权限/预算/保护沿用委托合同。
- 检查/证据：同时打字+AI候选、位置漂移、重放、断线采用和恢复测试。
- 非范围：AI后台直接逐字操纵共享光标、关键词冲突合并。

### C2-06 离线与连接降级策略（3 点）

- 用户价值：网络波动时能继续阅读，清楚哪些改动尚未提交。
- 状态/Owner：待 C2-03/04；桌面/UI Agent。
- 任务：在线/重连/离线只读/未发送状态；短时本地操作缓冲的安全上限；退出提示和恢复；个人模式完全独立。
- AC：离线不显示云端已保存；默认只读缓存不产生双主；允许缓冲时明确未同步且重连冲突可审；关闭应用不静默丢缓冲；个人本地作品不被协作连接状态影响；服务端拒绝后保留可导出文本。
- 检查/证据：网络切换、进程退出、拒绝/冲突和缓存隔离测试；用户桌面验收。
- 非范围：无限离线多人编辑、SQLite与云端自动双向同步。

### C2-07 多人协作端到端与安全验收（3 点）

- 用户价值：证明作者、编辑、评论者和查看者能共同完成章节且不会越权或丢稿。
- 状态/Owner：待 C2-01～06；验证 Agent，真实外部测试账户需用户明确授权。
- 任务：四角色、两设备、评论→建议→采用、同时编辑、AI建议、断线恢复、成员移除、发布锁定、导出；记录revision/actor/audit/sourceRoute。
- AC：四角色权限全部符合；并发与断线无静默覆盖；移除成员立即失去新访问；AI及人工署名完整；运行记录只读；个人本地数据零上传；失败恢复不重复应用。
- 检查/证据：隔离PostgreSQL/对象存储/mock模型长链；用户UI验收；安全门通过后才进入beta。
- 非范围：用mock证明公网容量、未经授权的真实邮件/付费模型、直接发布main。

## 多 Agent Wave

1. Wave C0.0：根完成 C0-01；身份、数据、权限三个 owner 并行提供证据，根冻结共享主体与工作区合同。
2. Wave C0.1：身份 C0-02、成员 C0-03 串行；权限 owner 在固定 DTO 上准备 C0-04；数据 owner只做迁入fixture。共享 schema/HTTP 由根接线。
3. Wave C1：版本 owner做 C1-01；评论/建议 Runtime 依次做 C1-02/04/05；通知与UI可在冻结接口后并行做 C1-03/06。
4. Wave C2：C2-02决策先行；实时网关、章节文档、UI离线由不同 owner 在边界冻结后并行；AI桥接等待文档合同；验证最后进入。

同一 checkout 中子 Agent 不切分支、提交或修改共享保留文件。身份、schema/迁移、共享类型、权限策略出口、HTTP挂载、Wiki、发布说明与阶段提交由根集成人统一处理。每个窗口通过定向检查和用户验收后进入 beta；不因文档存在而开放协作入口。

## Done 与安全门

每张卡必须有应用服务层授权、资源范围、并发/重放、失败恢复和审计证据；仅隐藏按钮、typecheck或WebSocket连通不算完成。数据库迁移只在隔离环境验证，任何用户数据迁入或破坏性步骤另行授权并先备份。前端视觉由用户验收，不默认运行浏览器或截图。
