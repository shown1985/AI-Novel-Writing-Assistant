# 独立发行版路线

`Release 1 / Release 2` 是产品范围里程碑，不是版本号。公开更新记录仍按日期标识；桌面安装包使用下文的独立版本线。

| 里程碑 | 核心结果 | 权威存储 | 访问边界 | 状态 |
| --- | --- | --- | --- | --- |
| Release 1 单机成书版 | 新手在一台电脑上从想法完成、恢复并导出整本小说 | 本地 SQLite；Qdrant 只存向量索引 | 桌面受控窗口或 `127.0.0.1`；无账号、不开 LAN | Active（试跑阶段） |
| Release 2 多人协作版 | 管理员、MFA、分权账号和多人共同维护作品 | MySQL 中央主库；SQLite 保留个人作品 | 认证后 LAN/在线访问 | Backlog |

先证明“完全不懂写作的人能在本机写完一本书”，再引入身份、云数据库和多人协作。Release 2 不得阻塞 Release 1。

## Release 1：单机成书版

### 目标

用户安装或启动应用后，不需要理解数据库、账号、Prompt 或小说理论，就能在同一台设备完成开书、规划、连续写章、暂停恢复、维护世界和角色、处理质量问题并导出正文。

### 范围

- SQLite 保存全部事实数据，已有数据不被隐式上传；默认只监听回环地址。
- 自动导演、章节生产、质量债、恢复、世界维护、人物和写法资产形成单机闭环。
- “AI 协作”指作者与本机 AI 协作，不是多人账号。
- 桌面开发启动、升级兼容、备份恢复和安装包验证进入发布门。

非范围：账号/MFA/工作区/评论/实时共编，MySQL 主库与云同步，公网服务与多租户。

### 平台决定

Release 1 桌面候选只支持 **Windows x64** 与 **macOS arm64**。macOS x64 不在本 Release 范围；如需支持，另立 Story 和验收入口。

### 当前阶段：试跑优先

截至 R1-S3L，已完成 22 个 Sprint、153 点，主要是运行时底座（诊断、模型调用证据、世界版本与 CAS、AI 结构补全幂等、发布门）。但**从想法到导出的完整链路还没有人用真实模型从头跑通过**：R1-02 的十章基线只用确定性 mock 和隔离 SQLite 证明了恢复、质量债和 TXT 导出，不覆盖公共 idea→导演交接、真实模型和 UI。

因此硬化工作暂停，下一步由 Owner 做一次真实端到端试跑（想法 → 自动导演 → 连续写章 → 暂停/恢复 → 导出）。试跑发现的问题决定优先级；[backlog](./backlog.md) 里预先写好的 Story 只作为候选，不再按原 Sprint 列车顺序推进。试跑做法见 [board.md](./board.md)。

### 原计划的后续窗口（候选，按试跑结果重排）

| 窗口 | 目标 |
| --- | --- |
| S3～S4 可信世界与修改闭环 | 世界版本、AI 评估、作者决定；提案→采用→复核在来源页闭环 |
| S5～S6 本机委托与预算 | 委托范围、模型策略快照、总预算、保存边界暂停与同任务恢复 |
| S6～S7 记忆与资产 | 本书记忆、正文/人物/规划局改、资产适配与发布保护 |
| S7 单机长链 | 有限撤回、导航收束、十章连续产出 |
| RC 发布候选 | 升级备份恢复、Windows/macOS 包装、第一本书验收、发布说明（R1-RC01～04） |

### Release 1 退出门

- 新手主链能在本机完成一本书，至少通过十章连续生产和中断恢复。
- 默认回环；没有账号时不存在可从 LAN 读取作品或模型密钥的路径。
- SQLite 升级、备份和恢复演练通过，作品计数与引用一致。
- 自动导演和章节生产遵守 completion-first / quality-first 政策，局部质量债不误停整书。
- Windows x64 / macOS arm64 启动与包装检查通过，用户完成 UI 验收。
- feature → beta 组合验证通过后才进入 main。

## 桌面身份与版本线（R1-G02）

背景：旧安装包的 appId、产品名、数据目录和自动更新地址都和上游相同。同时安装两者时会共用同一份 SQLite；自动更新还会下载上游安装包替换本发行版。这与 git 合并无关。

PO 决定（2026-09-25）：

| 项 | 决定 |
| --- | --- |
| 显示名称 | `Biz Novel Studio Next`（GA 前可改） |
| appId / Windows AUMID | `io.github.shown1985.biz-novel-studio-next` |
| 数据目录名 | `biz-novel-studio-next`；更新缓存目录 `biz-novel-studio-next-updater`；永不复用上游的 `AI-Novel-Writing-Assistant-v2` |
| 版本线 | major 从 1 起步，与上游 `0.x` 不重叠；公开 tag 只从 Release 1 GA 的 `v1.0.0` 开始，GA 前不打任何公开 tag 或预发布 |
| 发布目标 | 只发布到 `fork`；四处 owner/repo 指向本发行版；tag 与本地/`fork`/上游同名时拒绝，由 PO 跳号 |
| 旧数据 | 首次启动显式引导；用户确认后先备份，再**复制**（不移动）旧目录，生成图片一并复制，不复制日志 |

状态：G02a 版本线与碰撞门、G02b 发布/更新目标已在 R1-S3K 完成；G02c 身份拆分、G02d 旧数据复制引导、G02e 图片复制、G02g 审计加固仍在 Refinement。G02c 必须与 G02d/e **同批**合入 beta，否则已有数据的用户升级后会看到空库。版本 bump 到 `1.0.0` 属于 RC 发布卡。长期规则见 [桌面版本号与发布标识](../wiki/workflows/desktop-release-versioning.md)。

## Release 2：多人协作版（Backlog）

只允许不占用 Release 1 产能的只读 Spike/Refinement；账号、LAN 登录、MySQL 迁移和协作入口不得以半成品进入 Release 1。

关键决定：

- **存储**：阿里云 RDS MySQL 是中央协作事实源，不替换桌面 SQLite，也不靠复制 SQLite 文件同步。选定 MySQL 后，中心服务只保留 MySQL 主路径；PostgreSQL 仅在迁移兼容期存在。当前基础系列实例（1 核 1GB、无 SSL、无日志备份）只能用于隔离开发。
- **生产门**：高可用、TLS、私网优先、日志备份、恢复演练通过，应用使用独立最小权限账号。
- **认证**：服务端中央默认拒绝，前端保护只是体验。首位 Owner 只能凭宿主机交付的一次性设置凭证初始化，并在密码、TOTP、恢复码完成后原子激活；匿名网络请求不能重置认证状态。
- **协作**：评论和建议不是正文事实，只有有权成员明确采用后，才经资源版本安全写入正式内容。运行记录继续只读；邀请、评论、采用和恢复都在来源页完成。
- **迁入**：本地作品只在用户明确选择、预检和备份后复制到中心工作区，失败不损坏原库。

Sprint 列车：R2-S0 MySQL 决策与底座（DB-00～02）→ R2-S1 Schema 兼容（DB-03～06）→ R2-S2 认证基础（AUTH-00～03）→ R2-S3 管理员与账号（AUTH-04～10）→ R2-S4 数据迁入与工作区（DB-07～11、AUTH-11/12、C0）→ R2-S5 异步协作（C1）→ R2-S6 实时共编（C2）→ R2-RC。卡片清单见 [backlog.md](./backlog.md#release-2)。
