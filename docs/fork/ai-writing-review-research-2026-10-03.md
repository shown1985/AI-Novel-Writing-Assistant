# 小说与作文的「AI 味」检查调研

调研日期：2026-10-03。仓库基线：`codex/idea-input-dialog` / `cb4592e0`。

## 1. 调研范围与证据边界

本次核对论文、赛事官方材料、检测产品官方文档和本项目实际代码。没有调用真实模型、购买检测服务、上传作者正文、读取用户数据库或运行检测基准。

文中分别标注研究事实、代码事实和产品建议。论文数字只描述论文中的任务、样本、模型和指标；商业宣传不能视为本项目中文小说的验收证据。当前没有证据能给出本项目的检测准确率、最优评审模型或固定阈值。

## 2. 主要结论

1. 「表达自然度与套路感」「是否符合本书写法」「文本是否经过 AI 参与」是三个不同目标，应分别定义、评估和展示。
2. 小说与作文可共用评审编排、结构化证据、模型适配和修订预览，但必须使用不同文体量表与上下文。不能把小说的「避免主题总结」直接用于议论文。
3. 不同生成模型可以接受同一套文学质量标准；不同评审模型的分数与不同来源检测器的阈值，必须分别验证，不能默认等效。
4. 首期建议复用本项目写法引擎，交付可定位、有原因、可修改的表达问题。来源检测可作为另一个独立实验，不用未经校准的综合分声称「AI 含量」。
5. 本项目已有独立检测和改写入口，但有语义检测被字面量快扫跳过、分数混合多种含义、上下文不足与改写后缺少验收等缺口。当前应先验证已有能力，不再另建一套检测/修订系统。

## 4. 检查路线的比较

| 路线 | 能回答什么 | 所需能力 | 适合本项目的方式 |
| --- | --- | --- | --- |
| 词频、重复、句式统计 | 哪些表面现象频繁出现 | 本地统计 | 用作可解释观测、格式完整性检查或候选线索；不能独立判定作者来源或文学缺陷。 |
| LLM 结构化编辑评审 | 哪段表达存在问题、为什么、如何改 | 正文、文体量表、必要创作上下文、可返回结构化结果的模型 | 首期主线；复用现有 Prompt Registry 和写法引擎，用人类样本验证。 |
| 训练分类器/商业检测 API | 文本是否呈现训练语料中的生成特征 | 训练/校准样本或外部 API | 仅作为来源检测的独立试验。支持中文不等于适合中文文学，也不输出完整的写作改进判断。 |
| DetectGPT | 原文相对于扰动文本的概率曲率 | 对指定原文及扰动文本逐 token 评分，另需扰动模型 | 不必拥有生成器权重，但需要文本评分能力。普通聊天生成接口不能默认满足。[原论文](https://proceedings.mlr.press/v202/mitchell23a.html) |
| Fast-DetectGPT | 条件概率曲率 | 原文位置上的采样/评分模型条件概率分布 | 可使用本地代理模型；生成器黑箱不等于检测器无需 logits。少量 top-logprobs 不是完整分布。[原论文](https://arxiv.org/html/2310.05130v2) |
| Binoculars | 两个评分模型的困惑度与交叉熵比值 | 两个 tokenizer/词表一致模型在原文上的 logits | 适合开源研究对照。可以评估商业 API 生成的文本，但需另配评分模型并验证中文阈值。[原论文](https://proceedings.mlr.press/v235/hans24a.html)、[作者代码](https://github.com/ahans30/Binoculars) |
| 生成水印 | 是否存在特定生成系统写入的水印 | 生成时参与 token 选择、对应配置和检测器 | 检查的是水印，不是文风；不能事后给任意外部聊天模型输出补上可证明来源的水印。[Google 官方说明](https://ai.google.dev/responsible/docs/safeguards/synthid) |
| 本系统生成/修订记录 | 哪次操作、哪个模型生成或修改了保存版本 | 可信任务、版本和内容关联记录 | 对系统内来源更直接；只证明记录覆盖的操作，不能证明导入正文的外部作者身份。 |

DetectGPT 等论文所谓 black-box，可能指生成器不可访问而检测器另用代理模型；不是「任意聊天 API 的输出拿来评分即可」。水印未检出也不能推出纯人工，Google 文档明确深度改写、翻译会削弱水印检测置信。

## 6. 不同 LLM 应如何适配

### 6.1 先区分生成模型与评审模型

- 生成模型：待检文本来自哪个模型；导入作品往往未知。
- 评审模型：执行表达评审、给出问题证据的模型。
- 来源检测模型：判断训练过的生成统计特征的模型。

本项目检测接口中的 `provider/model` 选择的是评审模型，不是待检文本的来源。

### 6.2 共用什么，分别校准什么

共用文体语义量表、保护约束、结构化问题协议与验收指标。分别记录评审模型版本、Prompt 版本、上下文策略、temperature、有效思考配置，以及生成模型/生成条件（已知时）。思考强度更高、换一家评委或多数投票，都不能事先保证更准。

每个候选评审配置用相同盲测集验证问题证据正确率、关键问题召回、正常写法误报、重复运行稳定性和修订事实保持。没有数据前不将不同模型的 60 分视为同样严重，不给模型品牌绑定词表或固定风格缺陷。

来源检测另行做留出生成模型、留出文体、混写/改写和长度分组测试。阈值只在校准集选择，再冻结到独立测试集；测试标签不能参与阈值优化。

## 7. 适合首期的文体量表（产品建议）

这是结合文献和本项目目标的设计建议，不是已经验证的检测算法。

| 维度 | 小说/故事 | 作文 |
| --- | --- | --- |
| 具体性 | 描写与当前人物、场景、压力有关；情绪有原因与行动后果 | 观点有具体材料；经历和细节服务题目，不仅堆抽象词 |
| 个性与声音 | 对白符合人物关系、身份、知识边界；不能人人同一种腔调 | 保持作者观察与表达目的；论述与记叙口吻符合体裁 |
| 信息增量 | 每段增加事件、关系、视角或氛围；没有反复解释已呈现内容 | 每段增加论据、推理或观察；连接词不能掩盖逻辑跳步 |
| 修辞与重复 | 比喻、句式、情绪反应是否在语境中有效，是否跨场景反复套用 | 排比、总结是否有作用，是否只是同义重复 |
| 组织与兑现 | 场景压力、人物选择、章节目标、前后文连续性与结局兑现 | 审题、论点论据、推理、段落组织、结尾回应；说明文关注清晰准确 |
| 保留约束 | 事实、视角、人物动机、时间线、事件顺序、本书风格 | 题目限制、作者观点、已有事实、素材真实性、文体/篇幅要求 |

小说片段需附人物/场景/前后承接的最小必要上下文；作文需附题目、体裁、写作目的及评分要求。缺失时标明无法判断的维度，不凭空补人物经历或作文素材。正常童话重复、人物刻意口头禅、议论文总结等应有合法风格对照。

## 9. 最小可复用方案（尚未实施）

1. 复用写法引擎、注册 Prompt、结构化报告、修订预览与现有章节接收/质量债链；新产品 Prompt 仍必须纳入 `server/src/prompting/`。
2. 先明确文本类型、文体量表和保护上下文。文体未指定时可通过注册的 AI 结构化理解给出建议；不按关键词路由。
3. 报告区分已评审、上下文不足、未执行和调用失败；问题有文稿版本、原文位置、引用、维度、原因、修改方向及是否适合局部修订。引用存在性与范围可做确定性后校验，语义判断由 AI 负责。
4. 默认展示影响最大的少量问题和完整列表，允许无问题；不强迫每篇返回 4–8 条，不显示未经验证的 AI 百分比。
5. 修订先形成候选，逐项保留事实和作者意思；对被修改范围复查自然度与保护约束，再由来源页接受。结构问题不因表达修订被偷偷扩大到整章/整篇重写。
6. 完成优先策略下局部文风问题进入质量债/建议，不独立中断全书；质量优先策略已有的明确人工暂停按任务快照执行，不能由新综合分覆盖。

首期边界：小说表达检查先做闭环；作文量表可共享协议，但不顺带建设作文生产工作流。来源鉴定、模型品牌指纹、外部检测 API、生成水印和全书强制额外评审不属于此最小方案。

## 10. 可执行的小规模评测计划（尚未运行）

| 类型 | 数量 | 目的 |

### 标注与划分

- 分别标注来源过程和表达问题。来源人工/AI/协作不等于质量好/差；质量标签包括证据、影响、重要性、合法文风例外与不确定。
- 两至三名人工评审先盲评，分歧记录后裁决；来源身份、模型品牌隐藏。不要让生成模型自己提供「标准答案」。
- 按作者/原作品分组划分校准与测试，同一原文的全部变体留在同组；留出一个生成模型检查泛化。任何阈值冻结后才看测试结果。
- 先将作者/作品组划为开发/校准与独立测试两部分；用开发/校准部分中的 50 段筛选两种评审配置。最终验收仅使用未参与配置筛选、Prompt 调整或阈值选择的独立测试组，不把筛选样本重计入最终成绩。约 50 对原文/修订稿也从独立测试组抽取，盲化并交换展示顺序，测阅读改善与事实损失；若分组后不足 50 对，须补充新获授权测试组或减少配对数并报告实际数量。

### 分开报告的指标

| 目标 | 指标 |
| --- | --- |
| 表达问题检测 | 证据正确率、重要问题召回、正常写法误报、不确定/缺上下文覆盖率 |
| 模型评委 | 与人工一致性、交换顺序稳定性、重复运行稳定性、文体与模型分组结果 |
| 修订 | 人工偏好改善、人物/事件/观点/事实保持、未授权改动、文字增减与长文本耗时 |
| 来源检测（若另行做） | 人工误判率、各模型检出率、协作/改写/长度表现、阈值与置信区间；不只报总准确率 |
| 工程成本 | 调用数、输入/输出 token、耗时分位数、错误率与重试成本 |

100 个独立人工样本即使零误判，单侧 95% 二项区间上界仍约 3%；实际样本存在作者关联时更不能把它当作很低误判率的证明。各组样本更少，须显示样本量和区间。

模型费用按真实选定版本的输入/输出价格、实际 token 和调用上限计算，检测服务按其中文计费定义另计；本次不虚构固定金额或运行预算。比较价格前先约束可用性、误报和作者保护。

## 11. 后续优先级与研究空白

1. 优先验证并修复独立检测的字面量短路，以及未执行/无问题状态混淆。
2. 冻结小说量表与必要上下文，建立独立于来源标签的人工基准。
3. 用两种评审配置做证据与误报对照，验证候选修订保持事实；再决定是否扩大到作文量表。
4. 仅在明确需要来源鉴定时，对中文外部检测器或开源评分模型做独立实验，不让它们的分数改变文学质量结论。

仍未知：最新模型在本项目中文稿件上的优劣、不同思考档位的收益、外部检测器对未发布网文的实际误判、长篇跨章节成本、修订后事实保持率。研究报告不能替代这些实测。
