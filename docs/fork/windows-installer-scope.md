# Windows 测试安装包交付范围

## 用户价值

作者可在 Windows x64 安装并测试当前代码，包括世界开书、开局想法选择与 AI 实况反馈。使用既有 Electron 桌面运行时。

## 范围（4 点）

- 沿用已有 Windows 构建、staging、NSIS 安装包与包结构验证脚本，在 GitHub Windows runner 构建当前候选提交。
- 增加只读权限的候选构建入口，将安装包、来源提交与校验值保存为可下载的 Actions artifact。
- 候选包使用本地构建标识，运行时关闭公开自动更新；沿用 `desktop/package.json` 版本，候选身份由提交 SHA 标识。
- 检查构建、包结构与可用的隔离安装验证，提供安装包下载及未覆盖的验收条件。

## 非范围

不迁移 Tauri，不修改产品能力、桌面数据目录、应用身份或版本线，不晋级 beta/main，不打公开 tag、不上传 GitHub Release、不读取或打包用户小说、数据库和模型密钥。候选 artifact 不是正式发布。

## 依赖与文件边界

- 依赖 Windows runner、现有锁文件、桌面 staging 与验证工具，以及本发行版仓库 `shown1985/AI-Novel-Writing-Assistant` 的推送与 Actions 读取权限。
- 实现 owner 仅负责候选 workflow 和必要的构建入口；主线程负责工作树、提交、推送、构建结果跟进和文档。独立 QA 检查实际产物、来源 SHA、权限与敏感数据边界。
- 使用专属 `codex/windows-installer-*` 分支进行 push 触发；手动运行可使用相同 workflow。不得让候选入口具备公开发布权限或注入发布令牌。

## 验收与最窄验证

1. Windows x64 runner 从确定的提交完成构建，NSIS `.exe` 及 SHA-256 校验文件可下载。
2. artifact 包含准确版本、来源 SHA 与构建渠道；只上传白名单安装产物，不上传 staging、数据或配置目录。
3. 包结构验证通过；可用的隔离安装验证在临时 runner 自建目录运行，不接触用户数据或真实模型。Windows 页面体验和真实模型生成留给用户验收。
4. 工作流顶层和 job 均为 `contents: read`，实际构建不调用发布脚本、不写 Release、不创建 tag。复用现有发布目标静态门和独立差异评审。

当前新增部分属于构建交付工具，产品功能已在完整未推送范围的发布说明中记录；不为内部打包入口追加用户发布说明。稳定的候选构建边界更新到 Wiki。

## 构建前评审

- 独立 QA 确认 staging 只复制声明的应用文件与网页构建资源，候选上传仅含安装文件和来源/校验信息，隔离验证只使用临时 Windows runner 自建数据。
- 构建前检查发现 electron-builder 在 CI 中会推断发布模式；现有包装入口通过独立包装策略显式禁止本地候选发布，覆盖长短参数、等号形式及重复/冲突参数。
- 包装策略及发行目标聚焦测试 22/22 通过，严格静态门为 12 PASS、2 既有 REVIEW（继承的 0.4.28 禁止公开发布、macOS x64 不在范围）；独立 QA 复核通过。
- 本阶段提交用于触发实际 Windows 构建；Windows 构建、隔离安装与产物校验尚待 runner 结果，不能用静态检查替代。页面体验与真实模型生成留给用户验收。
