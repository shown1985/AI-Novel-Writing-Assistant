# 分叉开发成果的整合边界

## 背景与原则

多个工作区可能从同一基线继续修改模型调用、Prompt、自动导演和桌面工具。最新提交时间只能说明最后一次提交的时间，不能证明一个分支包含其他分支的有效成果。直接选择整份文件的一侧，可能让新界面保留却丢失调用保护或恢复约束。

## 当前规则

- 先刷新远端，再核对提交祖先、补丁等价、实际文件差异和工作区状态。历史分支的未合并提交可能是被后续实现替代的代码，不能把数量当作必须引入的功能清单。
- 在从 `beta` 建立的专属整合分支解决冲突，保留来源提交和整合决策。普通功能、桌面候选和上游未合并开发快照分别核对，再进入集成基线；用户明确要求 main 整合时，在验证后推进本地 `beta` 与 `main`。
- 来源分支的旧交接文档不覆盖当前 fork 规则。发行版看板、历史与交接资料属于 `docs/fork/`；根看板及上游文档归属仍按 fork 规则处理。
- 合并成功仅表示文本冲突消除；自动合并的字段、路由挂载、Provider 能力分支、草稿恢复和状态投影仍需独立核对。

## 必须保护的契约

1. 模型调用：思考开关与深度使用对应端点契约，保留调用来源证据、单次传输和已有预算停止条件；不能因为合入另一个文件拆分而恢复旧的隐式重试。
2. Prompt：相同能力只保留一个执行模块，兼容门面保持稳定；资产版本与 Registry 一致，结构化验收与遥测不能因模块拆分丢失。
3. 自动导演：生产界面选择不改变用户已选章节范围和审校/修复开关。已保存的人工暂停优先于后台租约恢复；读取缺失关联流水线不能覆盖原暂停原因。
4. 草稿与创作来源：URL 负责初始化，初始化后的表单选择负责当前绑定。承接方案必须匹配当前模式与拆书 ID，异步结果不能覆盖已切换来源或用户编辑。
5. 桌面：身份、版本线、数据目录和发布目标单独核对；main 合并不自动授权打 tag、上传公开包或推送远端。候选构建成功不代表整合后新源码已获得相同安装验证。

## 验证边界

新增迁移使用临时库比较全新结构与已有基线升级结构，保留旧行及历史迁移记录，并验证重复升级、外键和完整性。按实际改动选择运行契约测试；构建只证明可编译，不能替代状态恢复和数据保护验证。

SQLite 并发夹具应在创建连接前建立与应用一致的 WAL 模式。Worker 的 `DATABASE_URL` 必须显式指向其自有夹具库，因为导入模型或服务模块也可能初始化全局 Prisma；仅向被测服务注入客户端，不能证明所有模块连接都已隔离。发生 `SQLITE_BUSY` 时先区分导入初始化与业务事务，保留并发屏障和恰好一次调用断言，不用重试模型掩盖锁冲突。

复用旧验证必须说明代码输入未改变。模型调用、Prompt 或迁移影响到桌面打包输入时，历史候选包仍只证明历史源码的产物，不能改写其来源 SHA，也不能声称是 main 的新安装包。

## 分支与工作区退役

- 判断分支是否完成，以提交祖先和实际补丁为准。PR 被关闭但未显示 merged，不代表其成果未通过其他整合进入主线；历史上游分叉也不能只为减少分支数量重新合入旧实现。
- 清理自己的远端功能分支时，先保证同一事务将成果保存到 `fork/main` / `fork/beta`，或确认远端主线本就包含这些提交。上游 `origin` 的分支属于上游维护者，不能作为本发行版的清理对象。
- 清理前在仓库外建立私有恢复目录：Git bundle 保存全部 refs；工作区和忽略文件单独归档，并核验内容。数据库、配置、安装包和验收日志不能依赖工作区归档工具的默认保存范围，因为该工具可能忽略被 Git 忽略的文件。
- 用户数据库、数据备份和正在用于验收的库不按临时目录名判断用途。清理完成后比对受保护文件的大小与校验值；当前依赖及构建输出保留，旧工作区的可重建产物可随工作区退役。
- 安装包的来源取自包内 manifest、实际 EXE SHA-256 和对应 Actions 产物摘要。下载目录旁的同名 manifest 可能属于另一次下载，不能据此给 ZIP 内旧失败安装包贴上成功标签；可用包应迁到固定交付目录，失败包独立归档。
