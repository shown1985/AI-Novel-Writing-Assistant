# 从世界样本开始创作

## Background

新手可能先对世界设定产生兴趣，再寻找人物与故事开局。如果必须先离开样本库、创建小说、再找世界选择器，会丢失创作来源，也增加重复选择。只把世界名称传给模型同样不足：名字不能表达规则代价、阵营压力和地点冲突。

## Decision

世界样本是自动导演的开书来源之一。列表上的“基于这个世界创作”进入既有自动导演创建页，并通过 `worldId` 带入参考样本。作者可先让 AI 提供开局灵感，也可写自己的想法，然后沿用方向候选与确认流程。打开页面不会自动发起模型调用。

## Current Rule

- 起始页展示实际选中的世界及手册入口，生成灵感沿用现有结构化 AI 能力；不另建世界开书生成链路。
- 无任务的新来源可以初始化世界选择；已有本地草稿（包括作者主动清除世界的选择）优先于来源参数。已创建任务的保存状态拥有最高优先级，不能被 URL 覆盖。
- 来源世界参与草稿隔离。不同样本与普通开书不可互相覆盖；无世界来源的历史草稿键继续兼容。
- 世界来源变化应重建页面状态，并使旧页面异步回调失活，避免旧任务创建响应导航回原来源。单纯创建任务并更新 `taskId` 不应重建页面，否则会打断候选生成；世界选择改变也要清空旧灵感并丢弃迟到响应。
- 开局灵感、故事星图与候选生成读取服务端样本内容，采用有长度边界的规划参考。外部名称不能代替服务端规则、势力、地点和冲突；生成失败后的重试和定向调整仍受同一世界约束。
- 指定的样本不可用时，应明确报错并让作者重新选择或清除世界，不能静默换成其他世界。
- 开书前的上下文读取只读样本，不创建本书世界、不写样本。确认小说后，沿用本书世界准备阶段建立独立副本与切片；章节生产继续使用 `WorldContextGateway`，不会直接依赖库中样本。

## 起始输入与开局灵感

起始输入是作者的创作要求，所选世界提供舞台和不可违背的事实。两者必须共同进入灵感上下文。非空输入中的人物身份、目标、具体事件、关系与排除偏好由 AI 识别并保留；五种灵感角度用于在这些要求内部寻找不同开局，不能为了满足某个角度标签而丢弃作者要求。输入为空时，AI 才依世界和创作偏好发散。

灵感入口采用项目统一弹窗承接生成、查看与选择，展示本轮所依据的输入和世界。关闭只返回编辑；明确选择使用后才替换起始想法。结果需展示完整正文与可点击的使用操作，不把核心选择放在长页面底部，也不依赖鼠标悬停才能发现操作。

生成按钮代表用本次输入生成，不能只展开历史缓存。修改输入、世界或基础偏好后，旧结果和迟到响应不得冒充新结果；发起新请求时显示本轮生成状态，失败时在同一位置提供重试。该规则只影响开局灵感选择，不改变自动导演任务或正文生产状态。

## 灵感生成的实时反馈

选择弹窗必须给视口保留明显留白，桌面采用宽幅布局并限制最大高度；短内容自然收缩，长输入和结果在内部滚动。生成反馈放在当前弹窗中，避免作者需要穿过遮罩寻找全局 AI 实况入口。

灵感沿用结构化调用已有的 `LlmLiveBroker` 流式事件及 `useLlmLiveFeed`，不能额外建立一套模型调用或伪造生成百分比。等待时显示持续计时；真实阶段、思考和内容来自模型事件。结果校验前的实时内容只供观察，不能作为可选灵感填入起始输入。实时通道断线时保留 HTTP 生成请求，并说明连接状态；只读观察失败不能把创作请求判为失败。

每次用户发起生成使用独立 UUID，通过该灵感端点的可选 `X-Idea-Inspiration-Id` 请求头传递到 Prompt 执行的现有 `itemKey` 观察元数据。端点校验格式，不带标识的调用继续兼容；同一次生成的自动重试保留该标识，用户点击重试或换一组创建新标识。弹窗仅展示同时匹配该标识与灵感 Prompt 的会话，防止历史缓存、迟到事件及其他窗口请求混入本轮。这是观察关联，不是任务 ID，也不覆盖模型来源追踪的 `requestId`。

## Failure Modes

- 来源参数改变而页面状态未重置，会把样本 A 的想法保存到样本 B 的草稿中。
- 每次渲染强制使用 URL 世界，会覆盖作者换选或清除的选择，并污染任务恢复。
- 只在第一次灵感生成附加样本，后续候选或单项调整容易脱离原世界规则。
- 在规划读取时调用生产 Gateway，会提前创建副本和切片，导致“浏览/选方向”产生未确认的写入。
- 按钮只检查“是否有结果”会在作者修改输入后重复展示旧灵感。只按世界 ID 判断迟到响应也不足：同一世界内修改想法必须使旧请求失效。
- 仅按 Prompt 或开始时间筛选实况会把其他窗口同时生成的内容混入；必须匹配本次观察标识。实时输出若直接作为可选结果，可能把未校验或重试中的结构化片段写入用户想法。
